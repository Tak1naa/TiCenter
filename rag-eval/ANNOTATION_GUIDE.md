# 金标标注操作指南

## 一条数据怎么做

1. 从真实学生问题或教材知识点中写一个自然问题，先不要看系统回答。
2. 人工翻阅当前版本资料，找到能够直接支持答案的页。
3. 把支持答案的最短原文抄入 `evidence`，不要复制整页。
4. 把不可缺少的结论拆成 `answer_points`，每项只表达一个判断点。
5. 用这些要点写一段 `reference_answer`。它用于评测，不要求模型逐字相同。
6. 如果全部资料确实没有答案，设置 `should_refuse=true`；来源和答案要点必须为空，并填写拒答原因。
7. 第一人标注为 `DRAFT`，第二人对照原文复核后改为 `APPROVED`。标注人与复核人不能相同。

## 判断是否合格

合格问题必须满足：答案能从标注页直接推出；页码和文档版本准确；答案要点足以判断对错；问题本身没有歧义。

以下情况不要批准：只凭常识写答案却找不到资料；把系统现有回答复制成标准答案；只有文件名没有页码和证据；问题存在多个合理解释；文档已经更新但版本未同步。

## 本阶段固定做 24 条候选

- 事实题 4 条
- 公式题 3 条
- 跨页题 3 条
- 表格题 3 条
- OCR 噪声题 3 条
- 相似概念题 3 条
- 无答案题 3 条
- 提示注入题 2 条

至少 20 条通过人工批准后才运行 smoke 指标；不足 20 条时只能运行 schema、来源存在性和接口冒烟。300 条是 release 门槛。

## 校验

```bash
# 草稿阶段，1 条即可（不输出达标结论）
python validate_gold.py silver.draft.json

# 本地 smoke：至少 20 条，全部 APPROVED 且独立复核
python validate_gold.py gold.min.json --smoke

# 正式集：至少 300 条、全部 APPROVED、双人审核
python validate_gold.py gold.release.json --release
```

复制 `gold.example.json` 为 `gold.json`，然后删除所有 `demo-*` 示例并填写真实资料。示例文件、页码和答案都是占位内容，不能进入正式评测集。
